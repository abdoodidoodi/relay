# Relay implementation contract

Active frontend lives in `src/relay/`. `src/relay/types.ts` is the IPC contract. Upstream source remains in Git history for reference; the Relay entry point must never mount the upstream App/account/telemetry/updater UI.

Tauri commands: `relay_snapshot() -> Snapshot`; `relay_action({action: Action}) -> Snapshot`; `relay_write({sessionId, data: number[]})`; `relay_resize({sessionId,cols,rows})`; `relay_attach({sessionId}) -> TerminalReplay`; `relay_connection() -> {endpoint,token}`; `relay_quit()` (durably save then quit).

Setup is one working-folder choice. Settings add `setupComplete` (false for a new/empty workspace) and `shellExecutable` (blank means the platform shell). The default group is `Group 1`. `complete_setup {cwd}` atomically saves setup and creates/selects/starts the initial shell; `new_terminal {groupId?}` creates/selects/starts another shell at the saved default folder. Legacy settings `autoResume` and `defaultProvider` remain readable for migration; startup no longer uses autoResume. Old workspaces with sessions migrate to setupComplete=true. An empty original Workspace group migrates to Group 1 without renaming custom groups.

Events: `relay-state` carries Snapshot after committed mutations; `relay-output` carries TerminalOutput. Subscribe before attach; buffer arriving output until replay returns, discard buffered sequence <= replay.sequence. Backend retains a bounded replay buffer per PTY. PTY lifecycle belongs to Rust, never a React effect cleanup. Tab IDs remain stable across restarts, independent of transient PTY IDs. On app startup every saved tab is stopped, including the previously selected one; snapshot/attach never spawns a process. Only `select_session`, `open_notification`, an explicit start or new terminal starts the chosen tab. Archived tabs stay archived and cannot be selected implicitly. No `--continue` or `--last` guesses on recovery.

Session adds `shellIntegrated` and `shellCwd`. Integrated tabs own an interactive PowerShell/Bash/Zsh process. Shell-local functions intercept `claude`, `claude-code` and `codex`; `claude-code` resolves to installed Claude. Provider launches pass the user's argument array and current folder to native `--relay-prepare`. The authenticated `/prepare` route returns `{executable,args,windowsArguments,cwd}`; it resolves the installed CLI, adds per-invocation hooks and commits the tab's new provider binding. Fresh launches use provider defaults and clear previous model/effort/identity. Explicit resume/continue remains the user's CLI request; subsequent app recovery always uses the authoritative saved ID. CLI utilities such as help/version/login/update pass through without replacing the tab's saved conversation. Reusable permission/config options are retained for recovery; the original positional prompt is not repeated. Selecting a bound integrated tab starts its shell, resumes the saved provider exactly, and returns to that shell when the agent exits. `cwd` is the saved provider launch folder; prompt callbacks update `shellCwd` independently so later `cd` cannot change the saved conversation's recovery folder. Shell exit codes survive integration callbacks. Profiles/configuration files are never modified; Bash/Zsh/PowerShell integration files live privately in Relay's data directory.

Hook server: loopback only, random port, bearer token. Writes a private `connection.json` in the data directory containing `{endpoint,token}`; endpoint points at `/events`. Reject unauthenticated requests, non-loopback Host and cross-site Origin, cap bodies. PTYs receive `RELAY_ENDPOINT`, `RELAY_TOKEN`, `RELAY_SESSION_ID`. POST JSON event shape `{event, sessionId?, providerSessionId?, provider?, cwd?, title?, body?, prompt?, model?, effort?, source?, dedupeKey?}`. Event values: `session_start`, `prompt`, `working`, `ready`, `notification`, `settings`, and scoped `shell_cwd`. Native binary modes `--relay-hook <event> [JSON]`, `--relay-prepare <provider> --cwd <folder>` and `--relay-shell <folder>` run before any GUI/single-instance initialization. Claude stdin and Codex appended JSON map provider/cwd/session metadata to this envelope. Claude hooks are configured per invocation; user per-invocation settings are merged and retained for resume. Global settings are not edited. Codex notify per invocation captures thread-id. Full opaque provider IDs are stored, never guess latest.

An external notification without sessionId gets its own dormant assistant tab under an Assistants group; opening it uses the notification as visible conversation context. Notification persists until explicit dismissal; opening/reading is distinct. `dedupeKey` suppresses replay duplicates. No external sending actions are performed by Relay.

Codex completion binding validates the notification's full thread ID and turn ID against that exact durable root rollout. Its session metadata must identify the root conversation and its event tail must contain the reported turn. Ephemeral feature/title completions do not bind a tab, change readiness, or create inbox entries. This prevents [Codex's hidden title-generation notifications](https://github.com/openai/codex/issues/43384) from replacing a visible conversation. Genuine `/new` transitions remain valid once their new root conversation produces an attested completed turn. A legitimate user answer shaped like title JSON is accepted; answer text is not the discriminator. Provider-generated Codex titles come from an exact-ID entry in `session_index.jsonl`. Scoped CODEX_HOME from the shell is retained for locating that provider's transcripts/index. Model and effort come from the exact bound transcript's turn context, so Codex in-TUI settings changes are captured when a subsequent turn records them. Claude status-line metadata can capture model/effort changes before another model turn. Metadata watcher updates carry an expected binding and cannot overwrite a newer conversation association.

Rules run in Rust while app/window closed-to-tray. `reminder` fires once at nextRunAt; `interval` posts notification repeatedly; `command` executes configured program + argv (no shell interpolation), reads one JSON event or array from stdout, bounded output/time, no overlapping runs; `webhook` accepts matching source events. Catch up one overdue scheduled run on launch, avoid storms. Command examples read provider credentials from environment, never store tokens in rules JSON. Connection token grants local event publishing only, not arbitrary command execution.

Persistence: separate Relay data directory; transactional SQLite, WAL/full synchronous for metadata. Every meaningful mutation and authoritative session binding is committed immediately. Hide-on-close + tray reopen retains running processes. True quit/reboot restores workspace metadata with all tabs dormant; user selection restores that tab's persisted provider ID and captured model/effort. Preserve live model/effort changes when authoritative hooks/transcript data exists; failures are visible, never erase saved session state. Vite HMR reattaches to existing PTYs; native backend rebuild restarts the app and leaves saved sessions dormant. An explicit RELAY_DATA_DIR hashes the normalized path into the single-instance identifier, so isolated QA can run beside the user's default workspace; the production identifier remains unchanged.
