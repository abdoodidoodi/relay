# Relay implementation contract

Active frontend lives in `src/relay/`. `src/relay/types.ts` is the IPC contract. Upstream source remains in Git history for reference; the Relay entry point must never mount the upstream App/account/telemetry/updater UI.

Tauri commands: `relay_snapshot() -> Snapshot`; `relay_action({action: Action}) -> Snapshot`; `relay_write({sessionId, data: number[]})`; `relay_resize({sessionId,cols,rows})`; `relay_attach({sessionId}) -> TerminalReplay`; `relay_connection() -> {endpoint,token}`; `relay_quit()` (durably save then quit).

Events: `relay-state` carries Snapshot after committed mutations; `relay-output` carries TerminalOutput. Subscribe before attach; buffer arriving output until replay returns, discard buffered sequence <= replay.sequence. Backend retains a bounded replay buffer per PTY. PTY lifecycle belongs to Rust, never a React effect cleanup. Tab IDs remain stable across restarts, independent of transient PTY IDs. No `--continue` or `--last` guesses on recovery. Restore only identified provider sessions; a new tab without any conversation yet can be shown stopped/unbound.

Hook server: loopback only, random port, bearer token. Writes a private `connection.json` in the data directory containing `{endpoint,token}`; endpoint points at `/events`. Reject unauthenticated requests, non-loopback Host and cross-site Origin, cap bodies. PTYs receive `RELAY_ENDPOINT`, `RELAY_TOKEN`, `RELAY_SESSION_ID`. POST JSON event shape `{event, sessionId?, providerSessionId?, title?, body?, prompt?, model?, effort?, source?, dedupeKey?}`. Event values: `session_start`, `prompt`, `working`, `ready`, `notification`, `settings`. Native binary mode `--relay-hook <event> [JSON]` reads Claude stdin or Codex appended JSON, maps provider hook payload to this envelope and posts with inherited env. Never open a UI for hook mode. Claude hooks configured per invocation via settings, never overwrite user global config. Codex notify per invocation captures thread-id. Full opaque provider IDs are stored, never guess latest.

An external notification without sessionId gets its own dormant assistant tab under an Assistants group; opening it uses the notification as visible conversation context. Notification persists until explicit dismissal; opening/reading is distinct. `dedupeKey` suppresses replay duplicates. No external sending actions are performed by Relay.

Rules run in Rust while app/window closed-to-tray. `reminder` fires once at nextRunAt; `interval` posts notification repeatedly; `command` executes configured program + argv (no shell interpolation), reads one JSON event or array from stdout, bounded output/time, no overlapping runs; `webhook` accepts matching source events. Catch up one overdue scheduled run on launch, avoid storms. Command examples read provider credentials from environment, never store tokens in rules JSON. Connection token grants local event publishing only, not arbitrary command execution.

Persistence: separate Relay data directory; transactional SQLite, WAL/full synchronous for metadata. Every meaningful mutation and authoritative session binding is committed immediately. Hide-on-close + tray reopen, true quit/reboot restores persisted provider ID and configured model/effort. Preserve live model/effort changes when authoritative hooks/transcript data exists; failures are visible, never erase saved session state. Vite HMR reattaches to existing PTYs; native backend rebuild restarts the app and resumes saved sessions.
