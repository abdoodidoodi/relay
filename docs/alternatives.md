# Foundation notes

Agentrium is the selected foundation for Relay: it already ships a native Tauri desktop app for Windows and macOS, a Rust PTY backend, a React interface, and an MIT license. Relay reuses the terminal foundation while adding durable session identity, hook events, and local command rules. This keeps the app small enough to hack on and avoids taking on a second terminal emulator or a remote service.

| Project | Reusable strengths | Fit and limits |
| --- | --- | --- |
| [Better Agent Terminal](https://github.com/tony1223/better-agent-terminal) | MIT, cross-platform Tauri app with agent SDK/app-server integrations and persistent sessions. | A credible runner-up. Its bundled Node sidecar and broader agent abstraction add runtime and maintenance scope; Relay uses direct native PTYs and focuses on durable notifications and layout. |
| [cmux](https://github.com/manaflow-ai/cmux) | Native Swift/AppKit macOS terminal, agent notification panel, CLI/socket automation, GPL-3.0-or-later. | macOS-only desktop app. Its separate [cmux-tui](https://cmux.com/docs/tui) provides a Rust mux and control socket, but it is a terminal UI. Windows support is uncertain: the product page lists Windows builds while the source setup guide says ConPTY support is planned. A detached mux preserves a live PTY while its server runs; it does not restore a process after reboot. |
| [Superset](https://github.com/superset-sh/superset) | macOS agent workspaces with terminal, browser preview, and code review features. | Windows is listed as unavailable and the repo uses Elastic License 2.0. It is an IDE-scale workspace, beyond the lightweight terminal scope. |
| [Termexo](https://github.com/gemron/Termexo) | MIT, Tauri/Rust/Angular, real PTYs, Claude/Codex native resume commands, lifecycle hooks, status alerts, and local SQLite workspace state. | A close architecture reference for Relay, but the desktop app currently targets Windows. macOS would need platform-specific PTY, credential, and notification support. The project's README says closing Termexo or stopping the PC ends running processes; after reboot, resume means launching the CLI against its saved provider session ID. |
| [Agent Console](https://github.com/buhuipao/agent-console) | Rust, cross-platform, dual MIT/Apache-2.0, workspace-grouped sessions, native CLI resume, status and alerts. | A useful lightweight control-plane reference, but it is a TUI with optional browser access rather than a native desktop GUI. It reconnects to processes it owns; other sessions resume from their saved provider transcripts. |
| [Alethe](https://github.com/Kc1t/alethe-agents) | Cross-platform Tauri/Rust/React app with grouped projects, PTYs, and Claude/Codex resume claims. | Early and feature-heavy, AGPL-3.0-or-later, and its README notes limited macOS/Linux validation and unsigned builds. |
| [ThinkTerm](https://github.com/RoversX/ThinkTerm) | Native macOS/Windows terminal clients and a persistent Rust/WezTerm multiplexer. | GPL-3.0-only and a much larger terminal/multiplexer scope. Its README does not document the provider-specific resume and status-hook behavior Relay needs. |

“Resume after reboot” cannot mean continuing the same PTY: the operating system terminates that process. A reliable restore stores the provider's authoritative session ID, working directory, and launch configuration, then invokes the provider's documented resume command. The CLI and provider decide whether that conversation is still resumable.
